<p>掉线本身不可怕，可怕的是掉的时候不知道掉在哪一段，只能整条换掉。ISP 住宅线路的问题通常出在三个位置：运营商侧链路、代理服务端、本地到代理这一段。下面先给量化方法，再给参数之间的连带关系，最后画一棵故障树，让你从现象一路倒推到具体一段。</p>

<h2>一、先分清三种「不稳」，处理路径完全不同</h2>
<p>用户说的「不稳定」，至少对应三种不同现象：时不时断一下、一直很慢、某些时段特别卡。三种的根因和处理方式几乎没有交集，混着谈只会越调越乱。</p>
<h3>间歇断开与持续变慢要分开统计</h3>
<p>间歇断开看的是断开次数和恢复时间，持续变慢看的是首字节时间和吞吐。建议连续采集三天，把两类指标分别作图，再判断属于哪种。</p>
<h3>把时间对齐到目标市场时区</h3>
<p>线路拥塞有明显的时间规律，用本地时间看容易误判。把日志时间统一换算到目标市场时区，晚高峰的位置立刻就清楚了。</p>

<h2>二、线路质量：用四个数字说话</h2>
<p>别用「感觉卡」来描述问题。四个数字够用：平均延迟、延迟抖动、丢包率、首字节时间。这四个指标能覆盖九成的线路判断。</p>
<h3>采集方法与采样量</h3>
<p>用 mtr --report -c 100 目标地址 看逐跳丢包，用 ping 连续两百次看抖动，用 curl -w 看首字节。采样量太少没有意义，至少连续跑十分钟。</p>
<h3>判断标准给个粗线</h3>
<p>跨太平洋线路，平均延迟一百八十到二百四十毫秒属于正常，抖动超过平均值的百分之三十就值得注意；丢包率持续高于百分之一，基本可以判定这条线不适合长期承载登录。以上为经验区间，仅供参考。</p>

<h2>三、心跳与超时：参数之间的连带关系</h2>
<p>这三个参数必须一起调，单独改一个往往把问题挪到别处。顺序是：先定超时，再定心跳，最后定重试。</p>
<h3>超时不能小于一个来回</h3>
<p>连接超时建议设为实测往返时间的四到六倍。跨洋线路往返两百毫秒，超时给十秒比较稳；给两秒等于自己制造超时。</p>
<h3>心跳周期要短于中间设备的空闲回收</h3>
<p>多数 NAT 设备的空闲连接回收在六十到一百二十秒之间，心跳设三十秒比较安全。心跳太长，连接会被中间设备静默丢弃，表现出来就是「闲置一会儿就断」。</p>

<h2>四、重连策略：退避曲线和上限</h2>
<p>重连写得太积极，会把一次小抖动放大成一次故障。合理的做法是有限次重试加指数退避，再配一个熔断窗口。</p>
<h3>退避序列与最大间隔</h3>
<p>第一次等一秒、第二次两秒、第三次四秒，之后翻倍但不超过三十秒。重试上限设三次，超过就判定为线路级故障，交给上层切换。</p>
<h3>熔断窗口设五分钟</h3>
<p>连续失败达到阈值后，暂停调用五分钟再探。没有熔断的话，脚本会在故障期间持续打满连接，把一条本来就拥塞的线彻底压垮。</p>
<h3>重连要区分「可重试」和「不可重试」</h3>
<p>超时、连接重置可以重试；鉴权失败、地址被回收这类重试一万次也没用，直接告警。把两类错误码分开处理，日志会干净很多。</p>

<h2>五、故障树：从现象倒推原因</h2>
<p>按下面的顺序问，每个问题都能用一条命令回答，问到第三个基本就能定位。</p>
<h3>第一层问：别的线路正常吗</h3>
<p>换一条同地区的线做同样操作。别的线正常，问题在这条线上；别的线也不正常，问题在本地网络或目标服务。</p>
<h3>第二层问：是本机到代理，还是代理到目标</h3>
<p>在代理机上直接请求目标地址，与本机经代理请求做对比。前者快后者慢，问题在本机到代理这一段；两者都慢，问题在代理之后。</p>
<h3>第三层问：是持续性还是时段性</h3>
<p>持续性多半是配置或限速问题，时段性多半是拥塞。这个判断决定了你是改参数还是换线路，方向错了再怎么调也白费。</p>

<h2>常见问答</h2>
<h3>心跳设得越短是不是越稳？</h3>
<p>答：不是。心跳过短会增加无效流量和连接开销，还可能触发服务端的频率限制。三十秒是常见折中值，具体看中间设备的空闲回收时间。</p>
<h3>ISP 住宅线路能不能跑到机房的延迟？</h3>
<p>答：通常不能。住宅线路走的是本地宽带接入，路径更长、跳数更多。追求低延迟应该换线路类型，而不是在同一条线上反复调参数。</p>
<h3>重试次数设几次比较合理？</h3>
<p>答：三次足够。超过三次还没成功，说明不是瞬时抖动，继续重试只会放大拥塞。把剩余处理交给熔断和告警。</p>
<h3>怎么证明问题在服务商一侧？</h3>
<p>答：准备两份记录：一条同地区对照线的同期指标，一份逐跳丢包报告。两份材料放在一起，责任划分就没什么可争的了。</p>

<h2>合规提示</h2>
<p>本文讨论的是自有线路的稳定性监测与参数调优，监测行为应限于自己采购的资源，不得对他人网络或目标服务进行压力测试。</p>
<p>使用代理服务须遵守服务商条款与当地法律，不得用于攻击、扫描或干扰他人系统。发现线路异常应通过服务商工单渠道反馈。</p>
<p>文中延迟、丢包等阈值来自常见跨洋线路的实测经验，仅供参考，实际标准应结合业务容忍度设定。</p>
